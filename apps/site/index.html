Every agent gets its own preview. Production gets only what you promote.

An agent deploys its worktree, uncommitted files included, to a private preview of its own. Staging follows every push; production runs only what you promote.

Deploy the worktree, not the branch

An agent deploys what its worktree holds, uncommitted files included, to a preview in its own slot, without pushing anything. It reads the URL and the logs, tries its change, and deletes the preview when it’s done.

  • Built to be scripted. With --json, every command prints one result document on stdout and one event per line on stderr, and its exit code says what happened.
  • Kept away from production. A token limited to previews:deploy and previews:delete can create, deploy and delete previews, but can’t deploy, promote or stop your long-lived environments.

Describe it once, in your repository

The manifest lives next to your code. piqueld reads it from the commit it deploys, and builds the services that come from the same repository at that commit, so a pull request changes the code and its deployment together.

  • Plan before you save. piquelctl app plan shows what saving a manifest would create, change or stop declaring, without saving it.
  • Promote, don’t rebuild. Staging builds main on every push. Production never builds: it runs the release staging ran, down to the exact images.

Private on your tailnet, from every device

Any route can be private. It then answers only to the devices on your Tailscale tailnet, wherever they are and whatever network they’re on, with a real HTTPS certificate. Previews are private by default, and one setting keeps a whole environment private.

  • The dashboard is a tailnet device. piqueld joins your tailnet as its own node, at https://piqueld.<tailnet>.ts.net, with no proxy or certificate to manage.
  • Tokens bound to your tailnet. Tie a token to a tailnet user or tag, and a leaked CI token is useless anywhere else.

Handled for you

The parts every deployment needs, kept up to date without you.

HTTPS and DNS

Certificates and records for every route, public or private.

  • Let’s Encrypt certificates, renewed
  • DNS-01 for private and wildcard routes
  • Records in Cloudflare or OVH
  • Cloudflare Tunnel, with no inbound port

Access and audit

Who can change what, and a record of everything they did.

  • Passkey accounts
  • Scoped API tokens
  • Permissions for each application
  • An audit trail that shows tampering

Operations

What keeps applications running, and tells you when they aren’t.

  • Generated, encrypted secrets
  • Volumes and one-shot jobs
  • Logs and notifications
  • OpenTelemetry export

Drive it from your browser, your terminal or your agent

Change an application from any of them. Saving never touches what’s running; deploying does.

  • Dashboard

    In your browser. Deploy, promote, restore and read logs, signed in with a passkey.

  • piquelctl

    On the command line, for you, your scripts and your agents, with JSON output and exit codes.

  • HTTP API

    What the dashboard and piquelctl both use, documented in OpenAPI.

Your first deployment

Three stops to your first application.

  1. 1

    Install piqueld

    curl -fsSL https://piqueld.dev/install.sh | sh
    Install on NixOS, or by hand
  2. 2

    Create your account

    Print a one-time setup link, open it, and sign up with a passkey. Then sign piquelctl in with it.

    piquelctl setup-link
piquelctl login
    Read how to create your account
  3. 3

    Deploy your first application

    Apply a manifest and deploy it in one step.

    piquelctl app apply --file piqueld.toml --deploy
    Read how to deploy your first application
