# Write the documentation

Read `docs/dev/documentation.md` in full before you write anything. It is the
documentation's writing guide, and everything below only points into it:

- **Where pages go:** the user guide (`docs/user`) or the developer guide
  (`docs/dev`), `docs/SUMMARY.md`, and which files are generated, so you
  change their source and run `just generate` instead of editing them.
- **Writing and Style:** how to write a page, with an example, and the outline
  every feature guide in the user guide follows.
- **Screenshots:** they are generated by `just docs-screenshots`, never taken
  by hand, through the specs in `tests/playwright/screenshots/`.
- **Links:** how to link to pages, anchors and repository files.
- **Building and checking:** `just docs` builds the book and checks every link
  and anchor.

Before you finish, run `just docs`, and `just docs-screenshots` if you
changed a page a screenshot shows. The `piqueld-dev` skill runs a development
instance to check that the commands and dashboard labels you document are
right.
