# Client generation

The Rust `generate_openapi` binary produces the OpenAPI 3.0 document at
`docs/openapi-v1.json`, then passes a client-specific copy directly to
Progenitor 0.11. It writes the resulting operations to
`crates/piqueld-client/src/generated.rs`, and the application manifest's JSON
Schema to `docs/application-manifest.schema.json`. All three artifacts are
prepared before any checked-in file is updated.

Run `just generate` after changing API metadata, shared wire contracts, or the
manifest. Run `just openapi-check` to compare all three artifacts without
modifying them. The
generator is behind the daemon's optional `openapi-codegen` feature, so normal
daemon builds do not compile it. Generation needs only the Rust toolchain; it
does not download a separate executable or require Java.

`config.json` replaces endpoint request and response schemas with their existing
`piqueld-core` types. Add a mapping when an endpoint introduces a new top-level
wire type. Schemas outside this list are removed from the client-specific copy
because the generated operations do not use duplicate model definitions.
Parameter constraints are also removed from that private copy so generated
methods keep primitive argument types; public wrappers and the server retain the
existing validation behavior. The copy also drops the readiness endpoint's 403
response, since Progenitor cannot type it beside the readiness 503 body, and the
exec WebSocket operation: generated WebSocket methods need an upgraded
connection that WASM builds lack, so `piqueld_client::exec` implements it by
hand for native targets.

Progenitor currently accepts one request media type per operation. The generator
selects `application/json`; the public client implements the apply and plan TOML
requests, and the streamed local snapshot upload whose `Content-Length`
Progenitor cannot set, through one shared adapter. Manifest and OpenAPI downloads remain
generated byte streams and are collected through the same 16 MiB bound as JSON
responses. A small generated-source substitution routes Progenitor's JSON body
decoding through that bounded collector as well. Generated operation prose is
kept as ordinary comments because it describes private methods and is not Rust
doctest code.

The served and checked-in specification remains the complete contract, including
all JSON and TOML media types. Only the private copy passed to Progenitor is
reduced. Edit endpoint annotations, the mapping configuration, or the generator;
never edit generated Rust.
